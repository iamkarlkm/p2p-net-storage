### Pipeline (25 items × 3 phases)

For each of the 5 modules (`p2p-db`/`p2p-core`/`p2p-sync`/`p2p-ws`/`p2p-im`) × 5 diagrams
(`01-architecture` / `02-workflow` / `03-sequence` / `04-dataflow` / `05-lifecycle`):

1. **Validate** `archify validate <type> <input.json> --quality showcase --json`
   - Pass iff `ok === true && diagnostics.length === 0` (showcase 10 checks)
2. **Deliver** `archify deliver <type> <input.json> <output.html> --quality showcase --json`
   - Pass iff `ok === true && artifact.bytes > 0` (expected ~710 KB self-contained HTML)
3. **Visual-check** `archify visual-check <output.html> --json`
   - **Do NOT use exit code** — overflowed-but-valid visuals still exit(1)
   - Receipt validity = `typeof containment_status === 'string' && containment_status !== ''`
   - FULL pass (very hard for complex layouts): `viewport_fully_contains_svg && scrollbars_ok`
   - PARTIAL pass (receipt-collection baseline): containment/readability/viewerChrome JSON populated

### Expected JSON Output Shapes (Receipt-Level Checks)

### Clean-Flow / Endpoint-Side-Direction Geometry Root Cause

Even with `fromSide` removed (auto-inferred sideOrigin), this diagnostic fires when
`expectedDirection` (semantic FROM→TO) conflicts with the actual geometric direction:

- `expectedDirection=leftward` REQUIRES `from.x > to.x` (right col → left col)
- `expectedDirection=rightward` REQUIRES `from.x < to.x`
- `expectedDirection=downward` REQUIRES `from.y < to.y` (row above → row below)
- `expectedDirection=upward` REQUIRES `from.y > to.y`

Authoring `fromSide/toSide` alone **does not fix this**; nodes/states `.col` / `.row`
must be re-ordered to match the semantic direction. Use `archify validate … --json`
with `evidence.expectedAxis / evidence.expectedDirection / evidence.from[] / evidence.to[]`
to diagnose each failing transition/flow exactly.
